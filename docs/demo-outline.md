# 演示与答辩材料大纲

## 1. 项目背景与目标

- 解决传统 Java 业务系统接入 AI 能力时的前后端分离、异步任务、回调状态管理问题。
- 交付可运行的“Java + Python + Vue”双端管理脚手架。

## 2. 系统功能演示

1. 管理员登录，展示动态菜单和按钮级权限。
2. 用户、角色、菜单管理，角色授权菜单树。
3. 日志、在线用户、缓存管理。
4. 数据看板展示真实统计。
5. 创建 AI 任务：文本摘要、关键词抽取。
6. 演示任务状态流转：排队 -> 执行 -> 成功，结果回显。
7. 演示失败重试、取消任务、AI 服务不可用提示。

## 3. 技术亮点

- JWT + Redis Token 管理，支持刷新、黑名单、在线用户。
- RBAC 动态菜单与按钮权限，前端路由由后端菜单树驱动。
- FastAPI 异步任务 + Redis 状态机，Java 与 Python 通过回调解耦。
- 回调签名校验与任务号幂等，避免结果重复写入。
- Flyway 数据库版本管理，Docker Compose 一键交付。

## 4. 答辩问题预案

### 为什么 AI 服务要独立部署？

AI 推理耗时且依赖 Python 生态，独立服务便于扩展算法、横向扩容，Java 只负责业务编排。

### 为什么用 Redis 存任务状态？

Redis 天然适合短暂状态存储，支持过期清理；Java 和 Python 都能读写同一份状态，避免双写数据库。

### 异步任务如何保证不丢不重？

任务号全局唯一，Python 回调携带任务号，Java 侧校验签名、状态机和幂等规则，终态任务忽略重复回调。

### 如果 AI 服务挂掉怎么办？

Java 创建任务失败时返回“AI 服务不可用”，任务标记失败；运行中超时由扫描任务标记失败，前端轮询终态后停止。
